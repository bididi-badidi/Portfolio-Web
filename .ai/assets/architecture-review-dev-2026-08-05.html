Make resume generation one canonical module

Strong ports & adapters

    direction LR

Problem

Prompt, schema, model, and document behaviour exists in parallel Python and TypeScript implementations; changes have no locality and the active Python path has no tests.

Solution

Keep one deep resume generation module; make web and CLI thin adapters, and remove the shadow implementations once behaviour is locked at the seam.

Wins

  • • locality: one resume truth
  • • leverage: web and CLI
  • • tests hit one interface
  • • two adapters justify seam

After · definition and execution co-locate

One place owns each action

Problem

The action interface is scattered across six modules, so declaration and execution drift; tests can pass while an action remains unreachable.

Solution

Deepen the chatbot action module so model facts, validation, approval facts, and dispatch stay local; keep browser side effects behind adapters.

Wins

  • • locality: action stays whole
  • • leverage: one registration path
  • • interface proves reachability
  • • drift becomes unrepresentable

After · modal becomes an adapter

Problem

Conversation state, request timing, placeholders, errors, action execution, and rendering live in one UI module; the timeout request survives after the race and no tests cover the behaviour.

Solution

Deepen a chat session module around the conversation lifecycle; let the modal render its outcomes and let tests substitute the owned HTTP adapter.

Wins

  • • locality: lifecycle concentrates
  • • interface is test surface
  • • modal only renders
  • • timeout behaviour survives refactors
